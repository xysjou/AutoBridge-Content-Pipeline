# 两篇 × 12 语种 API 试点：可运行候选交接

目标站：**autobridgetrade.top**。本次是在既有英文流程上补齐多语种环节，不新建四套服务，不需要四把 API Key。

## 已补齐

1. 真实任务输入：启源 Q05 纯电参考车型推荐、冷藏车采购指南，共 12 个来源 URL。它们是待抓取和审核的输入，不能当作已通过研究的证据。
2. 英文链路：沿用既有独立 Research、Writing、Review 请求。
3. 多语种链路：英文通过后，完整生成其余 11 种语言；每个语言单独发起审核，最多两轮返修。禁止漏段、漏 FAQ、改数字或伪造来源。
4. 交付：每篇每语言独立 Markdown，沿用深蓝 S05 的 H1、SEO Metadata、正文、FAQ、来源表和 Editorial Review 结构。
5. 恢复与费用：同一整体预算账本；全文单独归档，账本保留响应编号、模型、用量、费用和文件引用；重跑复用已完成结果，未知发送结果停止重发。
6. 云端入口候选：支持离线预检、仅查询模型可用性的 account-check，以及真实 execute。候选工作流仍是模板，未安装或启用。

## 验证结果

- 新增 14 项测试通过。
- 原有第二阶段 47 项、第一阶段 41 项测试通过；总计 102 项。
- 完整测试走过两篇英文的 6 个模拟响应，以及 22 个语言版本的翻译和独立审核，共 50 个模拟响应；得到 24 份文件，重跑没有新增模型请求。
- 同时测试了预算不足时不能报 24 份完成、来源失败时不能进入写作、独立审核拒绝、漏译、数字/URL/claim 映射漂移、账本/归档失败后不得盲目重发。

这些是离线程序证据，**不是 50 次真实 API 调用，也不是 24 篇新生成的真实文章**。此前聊天生成的稿件不会冒充本流程的 API 产物。

## 下一步如何启用

1. 审查候选代码及两篇任务，补齐独立选题去重结论；候选合入 integration 分支。
2. 经批准，把 `cloud_pilot/runtime/multilingual-manual.yml.template` 安装到 main 和 integration 的 `.github/workflows/cloud-pilot-manual.yml`。这是为手动运行所需的最小入口变更，不把全部试点工程合入 main。
3. 绑定获批代码提交号，沿用已建立的 `autobridge-pilot` 环境和 `OPENAI_API_KEY`。保留指定审核人、禁用管理员绕过和 integration 分支限制。
4. 先执行获批的 account-check，只查询两个模型的元数据，不生成文章。
5. 在**另一固定提交**中保存获批 plan、24 小时内核对的价格快照和 permit。许可绑定代码 SHA、工作流安装后的 main SHA、任务/规则/价格哈希、目标站、12 语言、阶段、预算及到期时间。这样避免“许可写进代码导致自身 SHA 永远变化”的问题。
6. 经首次付费运行授权后，设置受保护的许可指纹并开启执行；先跑两篇英文真实闭环，核对实际模型、响应 ID、Token 用量和费用记录。
7. 英文通过且预算允许时，以获批 full 阶段继续生成 24 份全文；复用英文结果及同一账本。不会因为换阶段清零费用。

完整字段和操作顺序见 `cloud_pilot/multilingual/README.md`。此候选不改变现有 PR #3 的 HOLD 状态，也不能直接打开 PR #3 旧入口当成本版执行。

## 预算及功能边界

沿用原 **整个试点 3 美元** 上限，没有擅自增加。保守预留规则可能在实际花满 3 美元之前停止，因此不承诺该额度能完成全部 24 篇或所有返修。到预算边界需报告实际进度，不得以聊天补稿冒充 API 完成。

支持 UTF-8 和声明为 GB2312/GBK/GB18030 的静态公开页面。没有绕过验证码、登录或访问限制，没有新增自动浏览器渲染、PDF 抽取、自动选题或每日定时任务。第一版先用这两个固定任务验证自动生产闭环。

生成结果只是待终审稿件。图片版权、同语种内链、正式 URL、人工终审及网站 SEO 技术验收仍属于发布前工作；不把程序通过等同 Google 收录。
